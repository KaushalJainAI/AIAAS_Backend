### Product bugs this run found (all fixed, all with regression tests)

1. **Runs died at half their iterations.** LangGraph's step budget was
   `max_iterations * 2 + 10`, written when the loop was `agent -> tools`; it is
   now four node visits (`agent -> tools -> curate -> steering`). The limit fires
   *before* the runtime can withhold tools and force a final answer, so a long
   run lost everything instead of ending with a partial result. Fixed with
   `STEPS_PER_ITERATION`, pinned against the graph's own node set; tool calls
   issued on the last permitted iteration are now dropped rather than dispatched.
2. **One network blip killed whole runs.** A single `httpx.ConnectError` failed
   two 20-minute runs, reported as the bare "OpenRouter error: " (that exception
   stringifies to ""). Connection failures and timeouts are now retried twice,
   only while nothing has been emitted, and errors always carry a name.
3. **A read timeout lost a 12-iteration close**, in the re-run after fix 1. Same
   retry now covers it.
4. **The dev sandbox could not parse a CSV.** `csv`, `io.StringIO`, `statistics`
   and `decimal` were not importable, so data tasks failed locally while working
   in the production sidecar.

### Re-run after fixes (analyst only, 3 attempts)

Attempts 2 and 3 passed both cases; attempt 1 lost the month-end close to the
read timeout that fix 3 then addressed. **No recursion errors at all.**

- **The analyst month-end close is the expensive case:** 100k-490k tokens per
